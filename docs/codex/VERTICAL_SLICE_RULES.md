# ToxicLands — Vertical Slice Rules

# Purpose

Prevent:
- feature creep;
- overengineering;
- uncontrolled expansion;
- premature complexity.

---

# Core Philosophy

ToxicLands is developed:
- slice by slice;
- system by system;
- validation first.

---

# Slice Rules

A slice must:
- be playable;
- be testable;
- have clear scope;
- deliver real value.

---

# Forbidden Slice Behavior

Never:
- work on multiple large systems simultaneously;
- build future-proof mega architectures;
- implement speculative systems;
- add systems “for later”.

---

---

# MVP Protection

Before adding a new feature, ask:

- Is this required for MVP?
- Is this required NOW?
- Does this improve atmosphere?
- Does this increase complexity unnecessarily?

---

# Complexity Rules

Prefer:
- simple systems;
- explicit code;
- minimal logic.

Avoid:
- giant abstractions;
- manager-heavy architecture;
- advanced frameworks.

---

# Validation Rule

A slice is complete only when:
- playable;
- stable;
- validated;
- committed.

---

# Atmosphere Rule

Atmosphere has higher priority than:
- quantity;
- complexity;
- visual detail.

---

# Identity Rule

Every slice must still feel like ToxicLands.
