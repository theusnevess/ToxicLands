# ToxicLands — Codex Workflow

# Purpose

Define the official operational workflow between:
- ChatGPT specialist chats;
- official documentation;
- Codex;
- GameMaker;
- QA.

This workflow exists to:
- preserve consistency;
- prevent scope drift;
- maintain project identity;
- ensure controlled implementation.

---

# Core Philosophy

ToxicLands is developed using:

> small vertical slices.

Priority order:

1. atmosphere
2. readability
3. gameplay clarity
4. consistency
5. performance
6. expansion

Never prioritize:
- feature quantity;
- complexity;
- spectacle.

# Official Workflow

## Step 1 — Proposal

An idea is proposed in:
- specialist chats;
- Hub;
- roadmap discussions.

---

## Step 2 — Validation

ToxicLands Hub validates:
- consistency;
- atmosphere;
- scope impact;
- MVP relevance.

---

## Step 3 — Documentation

Official docs are updated BEFORE implementation.

---

## Step 4 — Task Definition

A small implementation task is created.

Tasks must:
- be minimal;
- be explicit;
- have acceptance criteria;
- avoid ambiguity.

---

## Step 5 — Codex Implementation

Codex:
- reads docs;
- reads active task;
- implements minimally;
- avoids unrelated changes.

---

## Step 6 — QA Validation

QA verifies:
- atmosphere;
- readability;
- scope;
- regressions;
- consistency.

---

## Step 7 — Commit

Only validated work should be committed.

---

# Development Rules

Always:
- implement one task at a time;
- preserve MVP scope;
- keep systems small;
- validate constantly.

Never:
- implement multiple systems simultaneously;
- redesign architecture impulsively;
- add unapproved features;
- overengineer early.

---

# MVP Rules

Current MVP goal:

Saimon leaves Vila dos Filtrados, explores a toxic field, defeats one mutant plant, retrieves a filter component, and returns.

Anything outside this scope:
- requires approval;
- must not be implemented casually.

---

# GameMaker Rules

Official engine:
- GameMaker
- GML

Architecture philosophy:
- simple;
- readable;
- minimal;
- iterative.

Avoid:
- giant managers;
- excessive abstractions;
- premature frameworks.

---

# Task Completion Rules

After implementation:
- summarize changed files;
- explain validation process;
- describe what was intentionally NOT implemented.

---

# Forbidden Behaviors

Never:
- change engine;
- add multiplayer;
- add procedural generation;
- introduce massive systems;
- contradict lore;
- break atmosphere;
- create generic cyberpunk aesthetics.

---

# Project Identity Protection

ToxicLands must always remain:
- atmospheric;
- oppressive;
- rural;
- biopunk;
- ecological;
- uncomfortable;
- grounded.
